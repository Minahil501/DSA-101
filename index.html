Array

contiguous · fixed-size · index-based

An array stores elements back-to-back in memory, so any slot can be reached instantly if you know its index. The trade-off: adding or removing from the middle means shifting everything after it.

array holds 6 slots max

Key features

  • O(1) random access via index
  • Elements stored contiguously in memory
  • Insert/delete in the middle costs O(n) — everything shifts
  • Cache-friendly: great for sequential scans
// insert value at index (shifts right)
void insertAt(int arr[], int& n, int idx, int val) {
    for (int i = n; i > idx; i--)
        arr[i] = arr[i - 1];
    arr[idx] = val;
    n++;
}

// remove value at index (shifts left)
void removeAt(int arr[], int& n, int idx) {
    for (int i = idx; i < n - 1; i++)
        arr[i] = arr[i + 1];
    n--;
}

Linked List

nodes · pointers · dynamic size

Each node holds a value and a pointer to the next node. Nothing needs to be contiguous, so growing or shrinking the list never means shifting other elements.

empty list

Key features

  • O(1) insert/delete at the head — no shifting
  • O(n) to reach a specific position (no random access)
  • Grows and shrinks dynamically, one node at a time
  • Backbone of stacks, queues, and hash-table chaining
struct Node {
    int data;
    Node* next;
};

// insert at the front
void prepend(Node*& head, int val) {
    Node* n = new Node{val, head};
    head = n;
}

// insert at the end
void append(Node*& head, int val) {
    Node* n = new Node{val, nullptr};
    if (!head) { head = n; return; }
    Node* cur = head;
    while (cur->next) cur = cur->next;
    cur->next = n;
}

Stack

1)implementtation_stack.cpp

LIFO — Last In, First Out. Only the top element is ever visible or reachable, like a stack of plates.

stack empty

Key features

  • Push and pop both run in O(1)
  • Only the top element can be accessed directly
  • Powers function-call stacks, undo/redo, and DFS
  • Used to check balanced brackets and evaluate expressions
class Stack {
    int arr[100], top = -1;
public:
    void push(int val) { arr[++top] = val; }
    int pop() { return arr[top--]; }
    int peek() { return arr[top]; }
    bool isEmpty() { return top == -1; }
};

Queue

5)queue_using_template.cpp

FIFO — First In, First Out. Elements leave in the same order they arrived, like a line at a counter.

queue empty

Key features

  • Enqueue at the rear, dequeue from the front, both O(1)
  • Preserves arrival order — fairness by design
  • Drives BFS traversal and task/print scheduling
  • Circular queues reuse freed space without shifting
template<typename T>
class Queue {
    T arr[100]; int front = 0, rear = -1, count = 0;
public:
    void enqueue(T val) { arr[++rear] = val; count++; }
    T dequeue() { T val = arr[front++]; count--; return val; }
    bool isEmpty() { return count == 0; }
};

Binary Search Tree

14–17) BinarySearchTree*.cpp

Every node keeps everything smaller to its left and everything larger to its right, so search, insert, and delete can all skip half the tree at each step.

empty tree

Key features

  • O(log n) search/insert/delete when balanced
  • In-order traversal visits nodes in sorted order
  • Degrades to O(n) if it grows lopsided — AVL/Red-Black trees fix that
  • Natural fit for range queries and ordered data
struct Node { int val; Node *left, *right; };

Node* insert(Node* root, int val) {
    if (!root) return new Node{val, nullptr, nullptr};
    if (val < root->val) root->left = insert(root->left, val);
    else root->right = insert(root->right, val);
    return root;
}

Min-Heap

20–21) max_heap.cpp / min_heap.cpp

A complete binary tree where every parent is smaller than its children — so the smallest element always sits at the root, ready in O(1).

empty heap

Key features

  • Peek at the min (or max) in O(1)
  • Insert and extract both run in O(log n)
  • Stored compactly as an array — no pointers needed
  • Backs priority queues, heap sort, and Dijkstra's algorithm
// sift the last element up until heap order holds
void siftUp(vector<int>& h, int i) {
    while (i > 0 && h[(i - 1) / 2] > h[i]) {
        std::swap(h[i], h[(i - 1) / 2]);
        i = (i - 1) / 2;
    }
}

Graph

nodes + edges

A set of nodes connected by edges — models anything relational, from friend networks to road maps. Watch BFS spread outward one layer at a time.

visit order will appear here

Key features

  • BFS explores level by level — shortest path in unweighted graphs
  • DFS dives deep before backtracking — great for cycle detection
  • Represented as adjacency lists or matrices
  • Foundation for maps, networks, and dependency graphs
void bfs(int start, unordered_map<int, vector<int>>& adj) {
    queue<int> q; set<int> visited;
    q.push(start); visited.insert(start);
    while (!q.empty()) {
        int cur = q.front(); q.pop();
        // visit(cur) ...
        for (int next : adj[cur])
            if (!visited.count(next)) { visited.insert(next); q.push(next); }
    }
}

Hash Table

22–23) FreqCounter / ProbabilityCounter

A hash function turns a key into a bucket index, giving near-instant lookups. Collisions are handled by chaining items in the same bucket.

7 buckets, hash = sum of char codes mod 7

Key features

  • O(1) average insert, lookup, and delete
  • Collisions are inevitable — chaining or open addressing resolves them
  • A good hash function spreads keys evenly across buckets
  • Backs unordered_map, caches, and deduplication
int hashFn(string key, int buckets) {
    int sum = 0;
    for (char c : key) sum += c;
    return sum % buckets;
}

// each bucket is a small linked list of (key, value) pairs

Trie

18) Project_TRIE.cpp

A prefix tree — each path from the root spells out a word, letter by letter, and shared prefixes share the same path. Ideal for autocomplete.

empty trie — pink nodes mark word endings

Key features

  • Lookup and insert run in O(word length), not O(n) words
  • Shared prefixes are stored once, saving space
  • Perfect for autocomplete, spell-check, and IP routing
  • Each end-of-word node is flagged so lookups know when a full word ends
struct TrieNode {
    TrieNode* child[26] = {};
    bool isEnd = false;
};

void insert(TrieNode* root, string word) {
    TrieNode* cur = root;
    for (char c : word) {
        int i = c - 'a';
        if (!cur->child[i]) cur->child[i] = new TrieNode();
        cur = cur->child[i];
    }
    cur->isEnd = true;
}

Red-Black Tree

self-balancing · colored nodes

A binary search tree that keeps itself roughly balanced by tagging every node red or black and following a small set of color rules. That keeps lookups at O(log n) even after lots of inserts.

root is always black

Key features

  • Every node is colored red or black — the root is always black
  • A red node can't have a red child (no two reds in a row)

Circular Queue

fixed-size ring buffer · wraps around

A queue backed by a fixed-size array where front and rear pointers wrap back to index 0 once they hit the end — so freed slots at the front get reused instead of wasted.

6 slots, empty

Key features

  • front and rear both advance with (i + 1) % size
  • Reuses freed space at the front — no shifting, unlike a plain array queue
  • O(1) enqueue and dequeue
  • Used in ring buffers, streaming data, and task schedulers
class CircularQueue {
    int arr[6], front = -1, rear = -1, size = 6;
public:
    void enqueue(int val) {
        if ((rear + 1) % size == front) return; // full
        if (front == -1) front = 0;
        rear = (rear + 1) % size;
        arr[rear] = val;
    }
    void dequeue() {
        if (front == -1) return; // empty
        if (front == rear) { front = rear = -1; return; }
        front = (front + 1) % size;
    }
};

Mirror BST

flip every left/right subtree

Mirroring a binary tree swaps the left and right child at every single node, recursively — the result is the tree's reflection, as if seen in a mirror.

build a tree, then mirror it

Key features

  • Swaps left and right at every node, recursively
  • Runs in O(n) — visits each node exactly once
  • Mirroring twice returns the original tree
  • A classic check in interviews: "invert a binary tree"
void mirror(Node* root) {
    if (!root) return;
    std::swap(root->left, root->right);
    mirror(root->left);
    mirror(root->right);
}

Bracket Check

balanced brackets · stack-based

Walk the string left to right: push every opening bracket, and on a closing bracket, it must match whatever is currently on top of the stack. If the stack empties out exactly when the string ends, it's balanced.

( [ ] ) { }
type a string of brackets and check it

Key features

  • Opening brackets get pushed onto a stack
  • A closing bracket must match the top of the stack, or it's invalid
  • Leftover items on the stack at the end also means invalid
  • O(n) time, O(n) space — one pass, one stack
bool isBalanced(string s) {
    stack<char> st;
    unordered_map<char,char> pair = {{')','('},{']','['},{'}','{'}};
    for (char c : s) {
        if (c=='('||c=='['||c=='{') st.push(c);
        else if (pair.count(c)) {
            if (st.empty() || st.top() != pair[c]) return false;
            st.pop();
        }
    }
    return st.empty();
}

Doubly Linked List

nodes · prev + next pointers

Like a linked list, but every node also points back to the one before it. That extra pointer makes it possible to walk backwards and delete the tail in O(1), which a singly linked list can't do.

empty list

Key features

  • Each node stores both a next and a prev pointer
  • O(1) insert/delete at both the head and the tail
  • Can be traversed forward or backward
  • Backs deques, LRU caches, and browser history
struct Node {
    int data;
    Node *next, *prev;
};

// insert at the end, O(1) with a tail pointer
void append(Node*& head, Node*& tail, int val) {
    Node* n = new Node{val, nullptr, tail};
    if (tail) tail->next = n; else head = n;
    tail = n;
}
